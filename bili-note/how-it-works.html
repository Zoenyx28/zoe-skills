01一条硬边界：谁做确定的事，谁做判断的事

整个 skill 就建在这条线上。搞反了，两边都会坏。

bili_note.py

确定性的事，交给脚本

  • 查 BV / 分P 列表（probe()）
  • 调 yt-dlp 下字幕
  • 去滚动重复（dedupe()）
  • 按停顿+字数切段（paragraph()）
  • 把时间戳拼成可点链接
  • 生成文件头、算落盘路径
你（Claude）

要判断的事，交给 agent

  • 读 .work/ 里的稿子
  • 判断哪句是知识点、哪句是口水
  • 按主题分节（不按时间）
  • 把口语改写成陈述句
  • 决定哪里该加粗
  • 把链接原样搬进笔记
为什么这条线不能挪

脚本没有任何办法知道「传输层」是一个小节标题、「套娃可以」是一句废话。 反过来，agent 每次手算 mm:ss → 秒 都会算错几个 —— 所以链接由脚本拼好，agent 只负责搬运。让每个人只做自己不会错的事。

03洗稿：把滚动字幕变成能读的稿子

三个动作，每个都踩过坑。

① 去滚动重复 — dedupe()

B 站滚动字幕是累积式的：后一条把前一条整个带上，只多几个字。 如果原样读，你会看到「大家好」「大家好我是」「大家好我是徐哥」—— 同一句话读三遍。

规则：len(prev_full) >= 4 才做前缀剥离 —— 否则「好」→「好的」这种短句会被误吃掉。 只在前一条够长时才动手，这一条是必须的。

② 切段 — paragraph()

两个信号，哪个先到就断：停顿 > 1.5 秒，或者累积字数 > 150。

⚠ 别改成只看停顿

实测 B 站 AI 字幕 103 条 cue 里 101 个间隔是 0 —— 它是一条没有停顿的连续流。 只看停顿，整条视频会粘成一块几千字的墙。字数上限才是这类内容唯一可靠的断段信号。

③ 挂链接 — 由脚本拼，agent 搬运

每段前面拼一条 [13:00](…?p=5&t=780)。 mm:ss 换算成秒很容易算错，所以这件事不交给 agent。 现实里我自己手打链接时就写出过 BV1LokeBhE69&p=5（少一个 ?）—— 这就是为什么「原样搬」是条硬规则，不是建议。

04为什么登录只能扫码

三条路都被堵死了，只剩这一条。

墙 1
读浏览器 cookie —— 解不开 这台机器的 Edge 是 155，cookie 用 App-Bound Encryption (v20) 加密； yt-dlp 的 WindowsChromeCookieDecryptor 只支持 v10 (DPAPI)。版本对不上，读出来是乱码。
墙 2
直接读浏览器凭据库 —— 被策略拦 去翻 Cookies / Local State 会被 Claude Code 的 Credential Exploration 策略拦住。实测被拦了两次，没有绕。
墙 3
让用户把 SESSDATA 贴进对话 —— 不可接受 那等于把登录凭据写进对话历史。这条从一开始就不在选项里。
✓ 剩下的路：扫码

全程不碰浏览器存储。login.py 生成二维码 → 渲染成本地 HTML 用默认浏览器打开 → 轮询 /x/passport-login/web/qrcode/poll → 成功后把 cookie 写成 yt-dlp 能吃的 Netscape 格式。

两个容易写错的地方
坑怎么处理
直接 os.startfile(url) 那个 url 是二维码载荷，本身是个移动端单页 —— 浏览器打开只会看到「App 登录页」。 必须先渲成本地 HTML 再开。
只从一处收 cookie 要收两处：poll 响应里的 Set-Cookie，和 data.url 那条 crossDomain URL 的 query（值还是 URL-encoded 的，得 unquote）。 只认一处，另一处形态一变就静默失败。
用 MozillaCookieJar 读回文件 它按系统默认编码打开文件，这台机器是 GBK，文件里任何非 ASCII 字节都抛 UnicodeDecodeError，而且 load() 不收 encoding 参数，绕不开。 → 自己解析 Netscape 格式。
解析出来的值没 strip() 每行 split 出来的值带着行尾换行，拼出的 Cookie 头里含 \n， http.client 直接抛异常 —— 被上层 except 吞掉， 就成了一个假的「未登录」。

05落盘认领：文件头里的两行是身份证

文件名只能告诉你「叫什么」，不能告诉你「是哪一集」。

同一个多P 视频的 194 集共用一个 BV。如果只用文件名匹配， P5 和 P5 之外的任何一集都可能撞上同一个 .md，然后把对方原地覆盖掉。

情况结果
同 BV + 同分P 重跑overwrite —— 覆盖原来那份（这是期望行为）
同 BV、不同分P不会互相认领 —— - 分P：P5 对不上 - 分P：P4
别的 BV 撞了同名renamed —— 退化成 <标题>-<BV>.md
单P 文件要求没有 - 分P： 这一行才算匹配
所以 header 由脚本生成、agent 原样粘贴

- BV： 和 - 分P： 这两行是认领的依据。让 agent 手拼， 它迟早会把这两行写歪 —— 代价是静默覆盖掉另一集的笔记。SKILL.md 里那句 「原样粘贴，一个字都别改」不是格式要求，是安全机制。

06事故复盘：?p=4 覆盖掉了真正的 P1

2026-10-10。这份 skill 里最重要的一次教训。

喂给 yt-dlp 的 URL产出的文件playlist_index
…/BV1LokeBhE69/?p=4NA_BV1LokeBhE69_p4.srtNone → 渲染成 NA
…/BV1LokeBhE69/ + --playlist-items 4004_BV1LokeBhE69_p4.srt4 ✓

两个参数表达的是同一件事，但只有后者保住了 P 号。

事故链
URL 带 ?p=4→ yt-dlp 当成单视频→ playlist_index = None→ 文件名成 NA_…_p4.srt→ 正则 (\d+)_ 匹配失败→ 兜底：{1: srts}→ 认领了真的 P1→ 覆盖

第 5 步是真正的成因。那句兜底是 if not by_index: by_index = {1: srts} —— 它把「识别失败」翻译成了「这是第 1 集」。数量核对也放行了：想要 1 集、拿到 1 集，通过。

三条修复

🧹
strip_page_param() — 喂给 yt-dlp 前先摘掉 ?p= 分P 只由 --playlist-items 表达。两个不能同时给。
🚫
page_of() 认不出来就返回 None 绝不返回 1。「认不出」和「这是第 1 集」是两件事，代码里不能长得一样。
🛑
删掉兜底，改成 die(code=6) + 集合比对 多出来的 P → 停（串号了，危险）；少了的 P → 只 warn（那一集本来就没字幕，不危险）。 这个区分是刻意的：不能因为一集没字幕就让整批停工。
最该记住的一条

我当时已经在 SKILL.md 里写下了正确的警告（「会渲染成 NA…静默归到第 1 集」）， 但代码里的兜底没删。文档写对了不等于代码做对了。
更普适的：「贴心的兜底」是危险源。一个把失败路径静默翻译成默认值的 fallback， 比直接报错危险得多 —— 报错你会看见，兜底你不会。

07退出码就是协议

脚本用退出码告诉 agent「现在该干什么」，不是「出错了」。点开看处置。

0ok

读 results，逐个写笔记。有 warnings 就一并告诉用户。

1error

把 message 原样转述给用户。

2need_config

还没设过输出目录。问用户 md 想存哪，再跑 set-output-dir。

3need_login

没有 cookies.txt。先跑第 0 步扫码登录。

4need_page_choice

多P 视频没选集。把 pages 列给用户选，再带 --pages 重跑。

5no_subtitle

没有可提取的字幕轨。陷阱：登录态失效也会长这样 —— 先跑 login.py --status 确认再下结论。

6page_mismatch

拿回的 P 号和要的对不上，什么都没写。转述 message， 别自作主张换 --pages 重试。

08使用技巧

按「什么时候会用到」排。

🔗
链接自带 ?p=N，就不用再给 --pages 直接 /bili-note <带 p=5 的链接> 就行，脚本会自己认。 只在多P 时认这个参数。
📚
一次抓多集：--pages 3-5 / --pages 1,3,5 支持区间和列表。某一集没字幕只会 warn，其余照常写 —— 不会因为一集拖垮整批。
✂️
稿子太碎或太整，调 config.json max_para_chars（默认 150）调大 → 段更粗；调小 → 断点更密。 pause_threshold（默认 1.5 秒）管停顿。只影响你看稿时的断点，不影响内容。
⚠️
.work/ 每次 run 会整个清空 先把稿子读完再重跑。重跑一次，上一批稿子就没了 —— 得重新抓。
🔑
怀疑登录态：login.py --status 返回 expired 就重扫，不用改任何配置。别去猜。
🔄
字幕突然全抓不到 → 换 bin/yt-dlp.exe 多半是 B 站改版。从 yt-dlp 官方 releases 下同名文件覆盖即可，脚本不用动。
🔒
绝不让用户把 cookie / SESSDATA 贴进对话 这是硬规则。诊断时也只打印 cookie 的名字，不打印值。
✍️
写笔记必须用 Write 工具 这台机器是 GBK 环境，走 bash heredoc 写中文会乱码。另外整个流程不要用 Bash 的 echo 写中文 md。
🎨
别只抄字幕，要总结成知识点 衡量标准：稿子里每一段都能指向笔记里的某一条要点，或者你能说清它为什么是纯口水。 80 段稿子收敛成 50 来条要点是正常的 —— 远少于这个数是跳段了，远多于就是没在总结。
