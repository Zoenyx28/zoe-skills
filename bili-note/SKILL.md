# bili-note —— B 站视频 → 知识点笔记

## 它是什么

`<B站链接>` 进 → 一份**知识点笔记**出。不是字幕转录，是把视频里的知识重新组织过的要点。

**分工，别搞反：**

| 谁 | 干什么 |
|---|---|
| `bili_note.py run` | 抓字幕、去滚动重复、切段、算落盘路径。**它不写笔记** |
| **你（agent）** | 读 `.work/` 里的稿子，写出要点，落到 `save_to` |

脚本能做的是确定性的活；"哪些是知识点、怎么归类"只能由你来判断。

```
~/.claude/skills/bili-note/
├── scripts/login.py        # 扫码登录，产出 cookies.txt
├── scripts/bili_note.py    # 抓取 + 洗稿
├── bin/yt-dlp.exe          # 抓取引擎
├── cookies.txt             # 登录态（扫码后才有）
├── config.json             # 输出目录 + 切段阈值
└── .work/                  # 洗完的稿子，每次 run 清空
```

## 登录只走扫码

本机 Edge 的 cookie 是 v20 加密的，yt-dlp 解不开；直接读浏览器凭据库还会被 Claude Code 的
`Credential Exploration` 策略拦。所以登录态一律由第 0 步的扫码产出。
技术细节（版本号、报错原文、issue 号）在 `scripts/login.py` 的头注释里。

## 怎么跑

约定：`$S` = 本 skill 目录的绝对路径（`~/.claude/skills/bili-note`，Windows 上形如 `C:/Users/<你>/.claude/skills/bili-note`），`PY = py -3`。下文的 `$S/...` 都按这个展开。

### 第 0 步：登录（只在没有 `$S/cookies.txt` 时）

```bash
$PY "$S/scripts/login.py"
```

脚本把二维码渲成本地 HTML 再**用默认浏览器打开**（打的是本地文件，不是 B 站页面 ——
直接开那个扫码 URL 只会看到 App 登录页），然后阻塞轮询最多 180 秒。

- Bash 工具的 timeout 给到 **240000**，否则你会先超时。
- 跑之前先告诉用户：「浏览器会弹出一个二维码页面，请用手机 B 站 App 扫一下」。
- 成功输出 `{"status":"logged_in","user":"...","verified":true}`。`user` 是用户名，
  可以用它向用户确认"登的是不是你"。
- **绝不要让用户把 cookie / SESSDATA 贴进对话。**

### 第 1 步：先看清楚是哪条视频

```bash
$PY "$S/scripts/bili_note.py" list "<链接>"
```

- `kind: single` → 直接进第 2 步。
- `kind: multi` → **把 `pages` 列给用户看，让他选**。列表可能有 194 项，
  只展示前若干项 + 总数 + 最后一项，并告诉用户可以指定区间（如 `3-5`）。

### 第 2 步：抓稿子

```bash
$PY "$S/scripts/bili_note.py" run "<链接>" [--pages 3-5]
```

`--pages` 支持 `3` / `3-5` / `1,3,5`。链接自带 `?p=N` 时不必再给 `--pages`。

`results[]` 里每条三项，都要用：

| 字段 | 是什么 |
|---|---|
| `draft` | 洗干净的稿子，**读它** |
| `header` | 文件头，**原样粘贴，一个字都别改** |
| `save_to` | 笔记落盘路径，脚本按落盘规则算好的 |

### 第 3 步：读稿子，写笔记

**稿子长这样** —— 每段一行，左边是可点回原片的时间戳链接：

```
[01:29](https://www.bilibili.com/video/BV1LokeBhE69?p=4&t=89) 来来制定规矩好吧来制定规矩那么参考模型就是用来制定规矩的...
```

**怎么写出要点：**

1. **按主题分节，不按时间。** 讲师换话题的地方就是节边界。节标题写那个话题本身
   （`## 传输层`），不写"第一部分""第二部分"。用 `##`，需要时再用 `###`。
2. **每条要点是一句陈述句**，保留术语原文（TCP / UDP / Mac 地址 / 数据链路层），
   去掉口头语（"好吧""对吧""兄弟们""我跟大家讲"）。是**改写**，不是摘抄。
3. **每条挂一个时间戳链接**，指向这层意思**开始讲**的位置。链接从稿子里**原样搬** ——
   `mm:ss` 换算成秒很容易算错，所以链接由脚本拼好，你只负责搬运。
4. **加粗关键词**，只加在讲师明确强调、或给了类比的地方（`**统一标准**`、`**物数网传会表应**`）。
5. **类比和例题照收。** "寄快递选邮政 vs 杂牌快递"配 TCP/UDP 是记忆锚，删了这节课就白讲了。
6. **相邻段落讲同一件事就合并；一段里讲了两件就拆开。**
7. **逐段扫，不许跳。** 稿子里每个新概念在笔记里都要有落点。

**写文件时**：`header` 原样贴上，空一行，然后写正文。用 Write 工具写 ——
这台机器是 GBK 环境，走 bash 的 heredoc 写中文会乱码。

**完成标准：稿子里每一段都能指向笔记里的某一条要点，或者你能说清它为什么是纯口水。**
做不到就是漏了，回去补。稿子 22 段左右的话，收敛成 20~35 条要点是正常的 ——
远少于这个数是跳段了，远多于这个数是没在总结、只是在照抄。

⚠ `.work/` 每次 `run` 会**整个清空**。先把稿子读完再重跑，否则得重新抓。

## 按退出码分流 —— 每个码都要如实告诉用户

| 退出码 | `status` | 你该做什么 |
|---|---|---|
| 0 | `ok` | 读 `results`，逐个写笔记（第 3 步）。有 `warnings` 就一并告诉用户 |
| 1 | `error` | 把 `message` 原样转述给用户 |
| 2 | `need_config` | 问用户 md 想存哪，然后 `bili_note.py set-output-dir "<路径>"` |
| 3 | `need_login` | 跑第 0 步的登录 |
| 4 | `need_page_choice` | 把 `pages` 列给用户选，再带 `--pages` 重跑 |
| 5 | `no_subtitle` | 明确告诉用户"这条没有可提取的字幕"，就停在这里 |
| 6 | `page_mismatch` | 拿回来的 P 号和要的对不上，**什么都没写**。转述 `message`，别自作主张换 `--pages` 重试 |

`no_subtitle` 有个陷阱：**登录态失效也会长这样**。先跑一次
`$PY "$S/scripts/login.py" --status` 确认，再下结论。

`ok` 里带 `warnings` 时（比如某一集就是没有字幕），其余集照常写。

## 落盘规则（脚本已实现，`save_to` 就是答案）

- 文件名：单P = `<标题>.md`；多P = `P003 <该P标题>.md`（194 集落一个目录才排得开）
- 清洗 Windows 非法字符 `\ / : * ? " < > |`，截断到 80 字符
- **同 BV + 同分P 重跑 → 覆盖**；**别的 BV 撞同名 → 退化成 `<标题>-<BV>.md`**
- 中间产物走系统临时目录，`.work/` 只放稿子，输出目录只有 md

`header` 里的 `- BV：` 和 `- 分P：` 两行是脚本认领旧文件的依据（多P 共用一个 BV，
不连 P 号一起比就会把 P4 的笔记写进 P3）。**这就是为什么 header 必须原样粘贴。**

## 切段怎么调

`config.json` 里两个可选键（不写就用默认值）。只影响**稿子**的段落粗细，
进而影响你写笔记时看到的断点，不影响内容本身：

| 键 | 默认 | 含义 |
|---|---|---|
| `pause_threshold` | `1.5` | 停顿超过这么多秒 → 断段 |
| `max_para_chars` | `150` | 单段累积到这个字数 → 断段 |

**嫌断点太碎就把 `max_para_chars` 调大**（如 300），嫌一段里话题跳得太快就调小。
两个键没有对应子命令，直接编辑 `config.json`。

## 维护

- **字幕突然全抓不到了**：多半是 B 站改版，先换 `bin/yt-dlp.exe`（从
  https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp.exe 下同名文件覆盖）。
- **登录态失效**：`login.py --status` 返回 `expired` 就重扫，不用改配置。
- **yt-dlp 参数改动**：`fetch_subs()` 里单P/多P 是**两套独立输出模板** ——
  单P 的 `playlist_index` 是 None，硬套 `%(playlist_index)03d` 会渲染成 NA，
  文件名解析会把所有 P 静默归到第 1 集。抓完的 P 号核对就是为了兜它。
- **分P 只由 `--playlist-items` 表达，URL 里的 `?p=N` 必须先摘掉**（`strip_page_param()`）。
  两个一起给的话 yt-dlp 会把它当单个视频，`playlist_index` 变 None、文件名成 `NA_...`，
  P 号整个丢掉。2026-10-10 实测踩过一次，代价是覆盖掉了一份别的笔记。
- **认不出 P 号时一律 `die`，永远不要 fallback 成 1**。这是上一行那个事故的真正成因：
  兜底把"识别失败"翻译成了"这是第 1 集"，于是覆盖了真的 P1。
